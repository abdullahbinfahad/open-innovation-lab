# Project Manifest Template

Every new project directory should include this completed manifest before implementation begins.

| Field                 | Required content                                                                       |
| --------------------- | -------------------------------------------------------------------------------------- |
| Project identifier    | A stable lowercase slug matching the roadmap record.                                   |
| Owner and maintainers | Named maintainers and expected review path.                                            |
| Scope                 | User problem, in-scope functionality, and explicit non-goals.                          |
| Platforms             | Supported operating systems, browsers, devices, or hardware.                           |
| Prerequisites         | Runtime, hardware, credentials, datasets, and legal/privacy requirements.              |
| Data handling         | Data classification, retention, export, deletion, and access model.                    |
| Validation            | Formatter, type checks, tests, build, manual acceptance checks, and measured criteria. |
| Release evidence      | Links to successful checks, version tag, changelog, and release notes.                 |

> A project remains **planned** or **in progress** until every listed validation condition has recorded evidence.
