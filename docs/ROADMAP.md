# Hard-to-Easy Roadmap

This roadmap is a public delivery contract rather than a completion claim. **Planned** projects have published design intent and validation criteria; **In progress** projects are being implemented; **Validated** projects have completed their required quality gates; **Released** projects have published versioned release evidence. ## Status transition policy

| From        | To          | Required evidence                                                                                               |
| ----------- | ----------- | --------------------------------------------------------------------------------------------------------------- |
| Planned     | In progress | A completed project manifest and tracked implementation work.                                                   |
| In progress | Validated   | Successful formatting, type checking, tests, production build, and every project-specific acceptance criterion. |
| Validated   | Released    | Version tag, changelog/release notes, and published release artifacts or deployment instructions.               |

> A project cannot skip a status or receive a validation label because it looks complete. Evidence must be available in version history, automated checks, or attached validation documentation.
